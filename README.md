# FoldBar

一个面向刘海屏 Mac 的轻量菜单栏收纳原型。点击菜单栏里的网格按钮，会像 Windows 的托盘溢出一样弹出 5 列图标面板。

## 当前功能

- 把分隔符左侧的真实菜单栏图标收纳到浮动网格面板。
- 分隔项只作为内部布局边界使用，不在菜单栏中显示额外的分隔符图标。
- 浮动面板按真实菜单栏从右向左排列：最靠近菜单栏右侧的图标在前，最靠左、最容易被刘海或系统容量隐藏的图标在最后。
- 没有收纳图标时不显示额外的空状态文案，而是让虚线拖放区填满标题下方空间，作为更大的菜单栏图标收纳目标。
- 悬浮面板使用更醒目的单行“FoldBar”标题，五列正方形图标格与加高的“保持可见”拖放区左右对齐，并统一使用 16pt 四周留白；开始拖动时，等高的图标预览显示蓝色反馈，拖放区立即显示浅蓝背景和蓝色边框，进入拖放区后只加深蓝色背景而不改变文案，松手或取消拖动后会清除提示状态。
- 悬浮面板顶部提供“展开”按钮；它会关闭网格，并在 FoldBar 箭头左侧、已有可见状态项之前的菜单栏区域铺开同一组可点击代理，避免代理覆盖真实图标，也不在代理后方绘制额外的矩形背景。再次点击 FoldBar 箭头会收起代理；真实图标仍留在 macOS 管理的原位置。
- “设置”可在浅色模式、暗色模式和高透明 Liquid Glass 之间切换，也可开启“直接拖动菜单栏图标（无需 Command）”；该开关默认关闭，修改后对下一次拖动立即生效。浅色模式使用透明度更低的背景板，高透明模式增强图标格模糊，各模式会分别维持图标与文字对比度。原生 Liquid Glass 需要 macOS 26，较低系统自动回退到浅色模式。
- 点击面板中的代理图标，FoldBar 会先撤掉代理，再用零长度分隔项一次性还原真实图标；代理条预先为 Control Center 无法消除的 16pt 最小状态项槽位留位，因此切换前后保持同一对齐，不会同时绘制两套图标，也不会在点击后突然左移。真实图标窗口到位后，FoldBar 还会等目标应用自己的可访问菜单项锚点同步到相同位置才转发点击，避免浮动面板仍从原来的屏外坐标展开。FoldBar 自己转发的鼠标抬起不会触发自动收起；如果目标仍被刘海遮挡，才会短暂收窄 FoldBar 箭头来腾出可点击空间，不改变真实图标顺序。
- 将鼠标停在面板图标格上时，优先显示真实状态项提供的原生 hover 帮助或可访问名称；macOS 统一托管窗口所显示的“控制中心”不再被当作各图标的名称。
- 把面板图标拖到上方的“保持可见”区域，应用会先临时让 FoldBar 自己的菜单栏图标腾出空间，等真实图标进入刘海右侧的可操作区域后，再用 macOS 原生的 ⌘-拖动语义把它插到 FoldBar 箭头左侧、紧靠箭头的位置；FoldBar 自己的图标随后立即恢复，并在确认真实图标位于该位置后重新折叠。系统拒绝自动拖动或没有落到指定位置时，菜单栏会保持展开以便手动调整。
- 打开面板后，始终可以按住 ⌘ 从菜单栏拖动一个可见图标；开启“直接拖动菜单栏图标”后，也可以不按修饰键直接拖动。FoldBar 会等指针移动至少 5 点才把普通按下识别为拖动，未拖动的普通单击仍会打开原图标。菜单栏拖动代理与面板格子拖动共用同一套蓝色背景、描边和圆角，并优先使用预热的真实图标截图，不再先闪出通用占位图；把代理放进面板或放到 FoldBar 箭头上，都会在菜单栏内部执行经过边界检查的 ⌘-拖动，将图标移到分隔符左侧并验证结果。松手在其他位置不会改变图标顺序。
- 在折叠前预先采集图标并保存在内存中；打开面板不再先闪现横向菜单栏。
- 折叠期间会检测后来启动或重建窗口的状态项，等待其稳定后计算箭头左侧容量：有空间时会尝试把真实图标放到可见侧；没有空间或 macOS 拒绝跨应用 ⌘-拖动时，图标继续留在溢出区并刷新代理缓存。自动放到可见侧属于尽力而为，不能当作所有 macOS 状态项都保证支持的行为。
- 保留图标原始宽高比；文字、温度和电量等宽图标会自动占 2–3 格。
- 自动保存有效的 `NSStatusItem Preferred Position`，降低 macOS 26 把图标永久停在屏幕外的风险。
- 退出前总会展开分隔符，避免应用退出后仍把其他图标留在屏幕外。
- 可选择登录时启动。

## 菜单栏图标如何进出面板

macOS 没有公开 API 可以把另一个应用的 `NSStatusItem` 直接放进自定义面板，也没有公开 API 可以改跨应用图标顺序。面板里显示的是实时截图代理，真实图标仍由 macOS 管理。因此：

- 从面板拖回菜单栏时，FoldBar 会短暂把自己的触发图标宽度收至零；空间仍不足时也会短暂收起分隔符占用的宽度。只有目标真实窗口完整进入当前显示器的可操作菜单栏区域、且箭头左侧容得下完整图标，才会模拟一次经过安全边界检查的 ⌘-拖动，并验证图标最终紧邻箭头左边；
- 从菜单栏拖进已打开的面板或 FoldBar 箭头时，FoldBar 不会让真实状态栏图标离开菜单栏，而是吞掉这段系统鼠标事件并显示截图代理；确认松手位于任一收纳目标后，再在菜单栏条带内部模拟 ⌘-拖动；
- 如果事件拦截、实时窗口识别、目标几何或移动结果中的任何一步无法确认，操作会停止并保持菜单栏展开，供用户手动调整。

这不是把图标“复制”进面板，而是一个尽量接近 Windows 交互、同时不依赖 Ice 私有 CGS API 的实现。

## 权限

- **屏幕录制**：只截取每个菜单栏小窗口，用于画网格图标；图片仅保存在内存中。
- **辅助功能**：在准备面板缓存时读取真实状态项提供的 hover 帮助，在面板打开期间识别并拦截用户主动发起的菜单栏拖动（默认要求按住 ⌘，可在设置中允许无修饰键拖动），以及在点击代理图标、收纳图标或拖到“保持可见”区域时发送对应的鼠标事件。

FoldBar 会用一次说明操作请求两项权限。macOS 仍会分别显示两个系统级确认——系统不提供合并隐私授权的 API——但 FoldBar 不会在每次点击时重复触发请求。

首次授予屏幕录制权限后，macOS 要求重新启动应用。Debug 与正式签名之间切换也可能导致系统重新询问权限。

## 构建

要求 macOS 14+、Xcode 16+、XcodeGen。

```bash
cd FoldBar
xcodegen
xcodebuild -project FoldBar.xcodeproj \
  -scheme FoldBar \
  -configuration Debug build
```

测试：

```bash
xcodebuild -project FoldBar.xcodeproj \
  -scheme FoldBar \
  -destination 'platform=macOS' test
```

工程已绑定当前开发团队，普通 Xcode 构建会使用同一 Apple Development 身份，避免因临时签名变化而反复丢失本机权限。公开分发仍需 Developer ID 签名和 Apple 公证。

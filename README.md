# FoldBar

一个面向刘海屏 Mac 的轻量菜单栏收纳原型。点击菜单栏里的网格按钮，会像 Windows 的托盘溢出一样弹出 5 列图标面板。

## 当前功能

- macOS 14–26 把 FoldBar 分隔符左侧的真实菜单栏图标收纳到浮动网格面板；macOS 27 及以上改用系统 `«` 的溢出边界。
- 旧系统的分隔项只作为内部布局边界使用，不显示额外图标；macOS 27 及以上不会注册该分隔项，避免零长度 `NSSceneStatusItem` 仍留下系统宿主空槽。
- 浮动面板按真实菜单栏从左向右排列，便于与“展开”后的系统图标逐一对照；即使多个应用被 macOS 放在重叠坐标，仍会保留每个公开的可访问菜单项。
- 没有收纳图标时不显示额外的空状态文案，而是让虚线拖放区填满标题下方空间，作为更大的菜单栏图标收纳目标。
- 悬浮面板使用更醒目的单行“FoldBar”标题，五列正方形图标格与加高的“保持可见”拖放区左右对齐，并统一使用 16pt 四周留白；开始拖动时，等高的图标预览显示蓝色反馈，拖放区立即显示浅蓝背景和蓝色边框，进入拖放区后只加深蓝色背景而不改变文案，松手或取消拖动后会清除提示状态。
- macOS 27 的 `«` 由系统负责真实图标的折叠与展开，FoldBar 以该系统边界区分“已折叠”和“仍可见”项目，不再注册旧版透明分隔项，因此不会在菜单栏中间留下宿主空槽，也不会把同一应用同时列在真实菜单栏和面板中。因此 macOS 27 面板顶部显示“关闭”；需要显示系统溢出图标时使用菜单栏的 `«`。macOS 14–26 仍显示“展开”并使用原有分隔符路径。
- “设置”可在浅色模式、暗色模式和高透明 Liquid Glass 之间切换，也可开启“直接拖动菜单栏图标（无需 Command）”；该开关默认关闭，修改后对下一次拖动立即生效。浅色模式使用透明度更低的背景板，高透明模式增强图标格模糊，各模式会分别维持图标与文字对比度。原生 Liquid Glass 需要 macOS 26，较低系统自动回退到浅色模式。
- 点击面板中的代理图标时，FoldBar 会重新验证对应的真实可访问元素与实时位置后再触发操作；身份或几何不能确认时会失败关闭。macOS 14–26 仍会用零长度分隔项临时还原真实图标；macOS 27 不伪造系统展开状态。
- 将鼠标停在面板图标格上时，优先显示真实状态项提供的原生 hover 帮助或可访问名称；macOS 统一托管窗口所显示的“控制中心”不再被当作各图标的名称。
- 把面板图标拖到上方的“保持可见”区域，应用会先临时让 FoldBar 自己的菜单栏图标腾出空间，等真实图标进入刘海右侧的可操作区域后，再用 macOS 原生的 ⌘-拖动语义把它插到 FoldBar 箭头左侧、紧靠箭头的位置；FoldBar 自己的图标随后立即恢复，并在确认真实图标位于该位置后重新折叠。系统拒绝自动拖动或没有落到指定位置时，菜单栏会保持展开以便手动调整。
- 打开面板后，始终可以按住 ⌘ 从菜单栏拖动一个可见图标；开启“直接拖动菜单栏图标”后，也可以不按修饰键直接拖动。FoldBar 会等指针移动至少 5 点才把普通按下识别为拖动，未拖动的普通单击仍会打开原图标。菜单栏拖动代理与面板格子拖动共用同一套蓝色背景、描边和圆角，并优先使用预热的真实图标截图，不再先闪出通用占位图；把代理放进面板或放到 FoldBar 箭头上，都会在菜单栏内部执行经过边界检查的 ⌘-拖动。macOS 27 会把完整图标移到系统 `«` 的折叠侧并用实时边界验证结果；macOS 14–26 则移到 FoldBar 分隔符左侧。松手在其他位置不会改变图标顺序。
- 在 FoldBar 进入折叠状态前预先采集代理图标并保存在内存中。macOS 14–26 使用菜单栏窗口截图；macOS 27 会通过公开的系统 `«` 控件短暂显示真实状态项，在其可见像素稳定后提取原始菜单栏轮廓、去除菜单栏背景并恢复系统折叠。这段内部展开与收回期间会显示当前菜单栏的像素级、不可点击静态快照，并关闭窗口缩放和淡出动画，避免真实菜单栏发生可见跳动；该快照不会进入图标截图。面板随后直接使用这些真实白色模板，而不是应用图标替代品；原始宽高比、实际视觉大小和居中位置均与菜单栏保持一致，打开面板本身不会再次展开系统项目。第一次点击 FoldBar 箭头打开面板，再点一次同一箭头会关闭面板。
- 折叠期间会检测后来启动或重建窗口的状态项，等待其稳定后计算箭头左侧容量：有空间时会尝试把真实图标放到可见侧；没有空间或 macOS 拒绝跨应用 ⌘-拖动时，图标继续留在溢出区并刷新代理缓存。自动放到可见侧属于尽力而为，不能当作所有 macOS 状态项都保证支持的行为。
- 保留图标原始宽高比；文字、温度和电量等宽图标会自动占 2–3 格。
- 自动保存有效的 `NSStatusItem Preferred Position`，降低 macOS 26 把图标永久停在屏幕外的风险。
- macOS 14–26 退出前总会展开分隔符，避免应用退出后仍把其他图标留在屏幕外；macOS 27 及以上由系统 `«` 管理溢出状态。
- 可选择登录时启动。

## 菜单栏图标如何进出面板

macOS 没有公开 API 可以把另一个应用的 `NSStatusItem` 直接放进自定义面板，也没有公开 API 可以改跨应用图标顺序。面板里显示的是代理图标，真实图标仍由 macOS 管理。macOS 14–26 可以使用实时窗口截图；macOS 27 不再公开独立状态项窗口，系统 `«` 又是真实溢出状态的唯一公开界面。因此 FoldBar 使用公开辅助功能身份与系统溢出边界构建代理列表，并只在折叠前真实项目可见时缓存其像素；不会保留持续占位的布局遮罩或伪造永久展开，抓图时只使用前述不可交互的瞬时防闪烁快照。因此：

- 从面板拖回菜单栏时，FoldBar 会短暂把自己的触发图标宽度收至零；空间仍不足时也会短暂收起分隔符占用的宽度。只有目标真实窗口完整进入当前显示器的可操作菜单栏区域、且箭头左侧容得下完整图标，才会模拟一次经过安全边界检查的 ⌘-拖动，并验证图标最终紧邻箭头左边；
- 从菜单栏拖进已打开的面板或 FoldBar 箭头时，FoldBar 不会让真实状态栏图标离开菜单栏，而是吞掉这段系统鼠标事件并显示代理图标；确认松手位于任一收纳目标后，再在菜单栏条带内部模拟 ⌘-拖动；
- 如果事件拦截、实时窗口识别、目标几何或移动结果中的任何一步无法确认，操作会停止并保持菜单栏展开，供用户手动调整。

这不是把图标“复制”进面板，而是一个尽量接近 Windows 交互、同时不依赖 Ice 私有 CGS API 的实现。

## 权限

- **屏幕录制**：用于 macOS 14–26 的菜单栏小窗口截图、macOS 27 折叠前的真实状态图标像素和短暂的防闪烁菜单栏快照，以及已在屏幕上可见的拖动预览；图片仅保存在内存中。macOS 27 不会为折叠区保留持续占位或接收点击的遮罩。
- **辅助功能**：读取公开的菜单栏可访问元素，在面板打开期间识别并拦截用户主动发起的菜单栏拖动（默认要求按住 ⌘，可在设置中允许无修饰键拖动），以及在点击代理图标、收纳图标或拖到“保持可见”区域时执行对应操作。macOS 27 也通过这项公开接口发现菜单栏项目和实时位置。

FoldBar 会用一次说明操作请求两项权限，系统仍会分别显示两个确认；FoldBar 不会在每次点击时重复触发请求。

首次授予屏幕录制权限后，系统可能要求重新启动应用。Debug 与正式签名之间切换也可能导致系统重新询问权限。

## 构建

要求 macOS 14+、Xcode 16+、XcodeGen。

开发或验证 macOS 27 的系统级兼容性时应使用 Xcode 27 / macOS 27 SDK；较旧系统路径仍可使用前述最低工具链。

```bash
cd FoldBar
xcodegen
xcodebuild -project FoldBar.xcodeproj \
  -scheme FoldBar \
  -configuration Debug build
```

测试：

```bash
xcodebuild -project FoldBar.xcodeproj \
  -scheme FoldBar \
  -destination 'platform=macOS' test
```

工程已绑定当前开发团队，普通 Xcode 构建会使用同一 Apple Development 身份，避免因临时签名变化而反复丢失本机权限。公开分发仍需 Developer ID 签名和 Apple 公证。
